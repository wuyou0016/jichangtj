## 先说结论

选机场时，你会反复看到这些词：**IPLC、IEPL、BGP、中转、直连、专线**。它们都在回答同一个问题：“数据从你这里到出口服务器，走的是哪条路？”

但这个问题对用户来说有一个麻烦的特点：**你看不到那条路**。线路是服务商内部的架构，页面上写的只是它的说法。所以本站对线路类型的态度是：写下来，标明是服务商或第三方的说法，**不替它背书**，并告诉你怎么用自己的测试去检验。

## 常见线路名词一览

| 名词 | 通常指什么 | 用户能否直接验证 |
| --- | --- | --- |
| 线路 | 从你到节点再到目标网站的整条路径 | 不能，只能通过延迟和稳定性间接感知 |
| IPLC | 点对点国际私有专线，不走公共互联网 | 基本不能 |
| IEPL | 与 IPLC 相近的国际以太网专线概念 | 基本不能 |
| BGP 线路 | 多家运营商接入、自动选路的入口 | 部分可通过多运营商对比感知 |
| 中转 | 入口服务器转发到落地服务器 | 有时能从延迟结构看出端倪 |
| 直连 | 客户端直接连到出口服务器 | 可通过延迟特征粗略判断 |

下面逐个说。

### IPLC 与 IEPL：专线是说法，不是保证

IPLC 和 IEPL 都被用来描述“点对点专用”的国际线路。宣传里通常把它们和“更稳、更低延迟”联系在一起。需要注意：

- 这是**服务商对架构的描述**，用户无法从客户端里直接验证；
- 就算架构属实，节点过载、晚高峰拥堵、你的本地运营商，都会影响最终体验；
- 同一家服务商里，不是所有节点都用同样的线路，宣传里的“专线”可能只是其中一部分。

所以看到“全线专线”“100% 专线”这类绝对表述时，要提高警惕：任何服务都很难做到全部节点、全部时段都一样。

### BGP 线路：重点在“入口”

在机场语境里，“BGP”通常指入口服务器接入了多家运营商网络，能按情况自动选路。它描述的是**入口侧**的特点，不等于整条路径都优质。是否真能改善体验，需要你在自己的运营商网络下对比测试。

### 中转：多一跳，利弊并存

中转架构里，你先连入口服务器，再由它转发到出口。好处是入口可以针对不同运营商做优化；代价是多了一个环节，入口过载或出问题时会影响整条线路。

## 宣传里常见的说法，怎么读

| 说法 | 可能的真实含义 | 建议 |
| --- | --- | --- |
| “全线 IPLC 专线” | 大部分节点使用专线 | 看自己测到的稳定性，别只信这四个字 |
| “单节点峰值 X Gbps” | 服务器带宽上限 | 与你实际可用速度无直接关系 |
| “晚高峰不降速” | 服务商的承诺 | 用一周自测验证，见下文 |
| “原生 IP / 流媒体全解锁” | 节点 IP 条件的描述 | 单独验证解锁，见[解锁怎么验证](/knowledge/streaming-unlock-verify/) |
| “企业级内网专线” | 一种营销说法 | 同样以实测为准 |

## 怎么用自己的测试去检验

线路好坏最终体现为**稳定的低丢包、稳定的延迟，尤其在晚高峰**。你可以这样做：

1. **多时段对比**：同一节点，白天、晚高峰各测一次，看延迟和丢包是否明显恶化；
2. **多节点对比**：同一地区，挑 2–3 个节点，排除“个别节点的问题”；
3. **关注波动而非平均**：忽高忽低的延迟，比偏高但稳定的延迟更难受，见[丢包、延迟、抖动](/knowledge/loss-latency-jitter-explained/)；
4. **用真实应用验证**：会议、游戏、视频，各用一次，记录断线与卡顿；
5. **按计划连续测**：按[一周自测计划](/knowledge/self-test-seven-days/)走一遍，比任何宣传都有说服力。

## 本站怎么处理线路信息

- 服务商或第三方说“专线”的，会写“专线（第三方转述）”之类的来源标注；
- 本站不会把“线路类型”当成排名依据；
- 排行榜和场景推荐依据的是**可核对的价格资料与站长自测的丢包率数据**，而不是线路的宣传名词。

如果你想看各服务商的线路描述与资料来源，请到各自的[详情页](/airports/)查看；想了解这些说法的整体风险信号，可以读[买前红旗清单](/knowledge/airport-red-flags/)。
